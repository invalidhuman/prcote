# Repository Instructions

## 코딩 테스트 문제 파일 규칙

새 문제를 추가할 때 문제 설명 Markdown과 아래 세 JavaScript 파일을 함께 만든다.

### Solution

파일명은 `<번호>_<사이트><문제번호>_<문제명>.js`로 작성한다.

- 사용자가 풀이할 `solution` 함수를 포함한다.
- 파일 마지막에 `module.exports = solution`을 유지한다.
- 직접 실행하는 테스트 케이스와 테스트 러너는 넣지 않는다.
- 사용자가 작성한 풀이와 주석은 요청 없이 수정하지 않는다.

### 코드 실행

파일명은 `<번호>_<사이트><문제번호>_<문제명>.test.js`로 작성한다.

- 문제 페이지에 공개된 예제만 검사한다.
- solution 파일을 상대 경로의 `require()`로 불러온다.
- 각 테스트의 입력값, 기대값, 반환값과 통과 여부를 표시한다.
- solution에서 발생한 `console.log` 출력도 구분하여 표시한다.
- 테스트 케이스끼리 영향을 주지 않도록 배열과 객체 입력은 복사하여 전달한다.
- 하나라도 실패하거나 예외가 발생하면 프로세스 종료 코드를 1로 설정한다.

### 제출 및 채점하기

파일명은 `<번호>_<사이트><문제번호>_<문제명>.judge.js`로 작성한다.

- 공개 예제 외에 최소·최대 입력, 경계값, 중복 등 문제에 적합한 테스트를 구성한다.
- solution 파일을 상대 경로의 `require()`로 불러온다.
- 입력값과 기대값을 숨기고 테스트 번호, 통과 여부와 실행 시간만 표시한다.
- 가능한 경우 정답을 하드코딩해 비교하는 대신 문제의 불변 조건과 결과를 독립적으로 검증한다.
- 실제 플랫폼의 비공개 테스트와 동일하다고 표현하지 않는다.
- 하나라도 실패하거나 예외가 발생하면 프로세스 종료 코드를 1로 설정한다.

### 문제 설명

문제 설명 Markdown에는 공개 테스트와 모의 채점의 차이 및 실행 명령을 기록한다.

```sh
node <문제명>.test.js
node <문제명>.judge.js
```

사용자는 solution 파일만 수정해도 두 테스트에 변경 사항이 반영되어야 한다.

### 공통 테스트 코드

동일한 출력, `console.log` 수집, 입력 복사 또는 시간 측정 코드가 여러 문제에서 반복되면 작은 공통 테스트 러너로 분리한다. 문제별 검증 조건과 테스트 데이터는 각 문제의 테스트 파일에 유지한다.
